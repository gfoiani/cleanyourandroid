# Clean Your Android

**Your phone, minus the bloat.** Turn off the manufacturer's telemetry, promotional push services,
preloaded partner apps and the Google apps you never open, from a computer, over a USB cable, with a
coding assistant that asks you before every choice. Then, if you want, battery-saving settings, one
choice at a time. No root, nothing flashed, and every step can be undone.

> [!WARNING]
> **Disclaimer: use at your own risk.** This project changes the state of system packages on your
> phone. It is built so that nothing is deleted and everything can be undone: packages are *disabled*
> (or, only where the phone refuses and you agree, removed for your user while their data is kept);
> a list of protected packages can never be touched; the state before every change is recorded and
> `tools/restore.py` puts it back. Even so, phones differ, firmware changes, and no list is tested on
> every model and version. **Back up your data before you start** (photos, chats, contacts, 2FA codes).
> The software is provided "as is", without warranty of any kind (see [LICENSE](LICENSE)); the authors
> are not liable for data loss, a phone that stops working as expected, a voided warranty, or any
> other damage. If something is unclear, stop and ask: doing nothing is always a safe choice.

## How it works

Every Android phone has the Android Debug Bridge (ADB). Switch on USB debugging, allow your computer
once, and the rest is standard Android tooling:

| Step | What happens |
|---|---|
| **Back up** | Your own backup of photos, chats and contacts first; then `tools/backup.py` saves the phone's package list and settings. |
| **Identify** | `tools/probe.py` reads brand, model, Android version, skin (OxygenOS, One UI, HyperOS...) and carrier, and picks the lists that fit. |
| **Choose** | `tools/compose.py --checklist` turns the lists into questions: *safe* groups need one OK, *ask* groups are one checkbox each, *expert* groups only if you want more. |
| **Apply** | `tools/disable.py` shows a dry run, then disables in small batches with `pm disable-user`. |
| **Save battery** | `tools/tune.py` offers battery settings (screen timeout, scanning while Wi-Fi is off, dark theme, Battery Saver...); only the ones you tick change, and each old value is recorded first. |
| **Check** | Screenshots after each batch, a reboot, then you test calls, SMS, data, notifications and unlock. |

What it never does: root, unlock the bootloader, flash, `pm clear`, delete an app that is not part of
the system image, or touch what a phone needs to work (calls, SMS, emergency alerts, contacts and media
storage, Play services, security updates, the keyboard, home screen and apps you are using). See
[`guards/`](guards/).

## Quick start

You need a computer with Python 3.9 or newer, [Android platform-tools](https://developer.android.com/tools/releases/platform-tools)
(`adb`), a USB data cable, and a coding assistant with shell access: Claude Code, Codex, Gemini CLI or similar.

| Where | What to do |
|---|---|
| **1. Your data** | Back up photos, chats, contacts and authenticator codes the way you normally do (Google One, your phone maker's cloud, a computer). |
| **2. On the phone** | Settings → About phone → tap **Build number** seven times (Xiaomi: *MIUI/HyperOS version*; Samsung: *Software information → Build number*) → back → Developer options → **USB debugging** on. Plug in the cable and tap **Allow** on the phone. |
| **3. On the computer** | `git clone` this repo, open the folder in your assistant, paste [`PROMPT.md`](PROMPT.md) and fill in your phone model. |
| **4. Answer the questions** | Which Google, brand and partner apps you use. Nothing you tick is touched. |

The assistant uses the tools in `tools/` rather than writing its own: that is where the dry run,
the protected list and the recovery record live.

## Supported phones

Any Android phone with USB debugging. Lists are **composable**: a list for the brand and its skin
version (`lists/brands/`), lists that fit every phone (`lists/google/`, `lists/common/`), carrier lists
(`lists/carriers/`), and tested lists for exact models in [`examples/`](examples/README.md).
`tools/probe.py` suggests the ones that match your phone.

## Doing it by hand

```bash
python3 tools/probe.py                                    # what the phone is, which lists fit
python3 tools/backup.py                                   # save package list and settings to backup/
python3 tools/compose.py lists/brands/oneplus/oxygenos-14.txt lists/google/optional-apps.txt \
    lists/common/partner-preloads.txt --checklist          # the questions to answer
python3 tools/compose.py <same lists> --drop-group "Gmail" --drop-group "Google Maps" \
    -o work/my-phone.txt                                   # your personal list
python3 tools/disable.py work/my-phone.txt                # dry run: shows, changes nothing
python3 tools/disable.py work/my-phone.txt --apply --group "OnePlus diagnostics and usage statistics"
python3 tools/screenshot.py shots/01-after.png            # look at the phone after each batch
python3 tools/restore.py work/my-phone.txt                # undo everything
python3 tools/tune.py tweaks/power.txt                    # battery settings: dry run, value now -> new
python3 tools/tune.py tweaks/power.txt --apply --group "Screen turns off sooner"
python3 tools/tune.py tweaks/power.txt --restore          # put the old values back
```

| Tool | What it does |
|---|---|
| [`probe.py`](tools/probe.py) | Identifies the phone and suggests lists. Reads only. |
| [`backup.py`](tools/backup.py) | Saves packages, settings and properties to `backup/`. Reads only. |
| [`compose.py`](tools/compose.py) | Merges lists, prints the checklist, writes your personal list. |
| [`disable.py`](tools/disable.py) | Dry run by default; `--apply` disables, `--group` for small batches, `--fallback-uninstall` only with your consent. |
| [`restore.py`](tools/restore.py) | Puts back the state from before; `--group`/`--package` to undo one batch. Never disables anything. |
| [`check.py`](tools/check.py) | After a system update: what came back on; `--fix` turns it off again. |
| [`tune.py`](tools/tune.py) | Battery settings from [`tweaks/`](tweaks/): dry run by default; `--apply` needs a `--group`; `--restore` puts the old values back. |
| [`screenshot.py`](tools/screenshot.py) | Saves a screenshot from the phone. |

Exit codes for every tool: `0` done, `1` done but something needs a look, `2` did not run.

## Undo

```bash
python3 tools/restore.py work/my-phone.txt                       # everything this list changed
python3 tools/restore.py work/my-phone.txt --group "Game Space"  # one group
python3 tools/tune.py tweaks/power.txt --restore                 # the battery settings
```

The recovery records are in `~/.cleanyourandroid/<serial>/`. A battery setting you changed yourself
after `tune.py` is left as you set it. Without a computer, a disabled app comes
back from the phone itself: Settings → Apps → (show system apps) → the app → **Enable**.

## After a system update

Updates can turn packages back on. `python3 tools/check.py work/my-phone.txt` lists them and exits 1;
`--fix` turns them off again with the same guards.

## FAQ

**Will I lose data?** Disabling an app keeps its data; a removal for your user keeps it too (`-k`).
Packages that hold your data (contacts, SMS, call log, media, cloned apps, secure folders) are protected.
Back up anyway: that is the rule.

**Will I still get security updates?** Yes. The system updaters are protected on purpose.

**Does it work without a SIM / on a work phone?** Yes for the first. On a phone managed by your
employer, ask them first; the tools only change your personal profile (user 0) and stop at device admins.

**Why not uninstall?** `pm disable-user` is fully reversible from Settings. Some phones refuse it for
a few packages; there, and only if you agree, the package is removed for your user and kept on the
system, and `restore.py` reinstalls it.
